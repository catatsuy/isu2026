# 海外ローカル読み取りの拡張・往復削減

2026-10-31 05:54 UTCに3台へ配置。配置バイナリのSHA256：
`1cdbd30202eaceb52a9c7c75eacb8c38bad2ca21b7eaa661046fc5b040e15666`。
PostgreSQLは引き続き非同期。Primaryと両Replica、画像の非同期複製構成は変更していない。

## 修正した問題

初回実装ではPrimaryを読むGETにもread-only transactionを追加し、BEGIN/ROLLBACKの往復と接続占有を増やしていた。
この変更はアジアにも適用されていた。共通読み取りトランザクションを撤去し、アジアは従来の直接Primary poolを使用する。
海外の通常GETも追加のBEGIN/ROLLBACKを発行しない。書き込みトランザクションは維持した。

## 現在のルーティング

isu01はPrimaryのみ。
isu02・isu03では、次のデータ取得をローカルDBに向ける。

- 自分・他人のプロフィール、ユーザー検索
- フィード、投稿詳細、自分の現在の投稿本文
- Memories、エクスポート
- コメント一覧、RealMoji一覧

ローカルで取った内容だけで権限を決定しない。
認証・IP制限・閲覧権限・現在の削除状態はPrimaryを使用する。

- 海外の認証とIP制限を1回のPrimary SQLへ統合。無効セッション・退会・IP banをそのリクエストで確認する。
- フィード・投稿の権限に必要なユーザー、投稿済み状態、ブロック、友達、二次友達を1回のPrimary SQLで取得し、そのリクエスト内で共有する。他のリクエストへ認証・権限をキャッシュしない。
- ローカル投稿候補のIDをまとめてPrimaryへ照合し、削除済み投稿、退会済み作者、公開範囲変更、終了した投稿期間、現在のフォロー状態を確認する。許可されない候補は返さない。
- ユーザー検索・プロフィールではPrimaryのactive状態、ブロック、認定種別、友達関係で返却とbio公開を判定する。
- コメント・RealMoji・Memoriesのローカル内容から、Primaryで削除・置換済みのものを除外する。
- 自分の現在の投稿IDと投稿可否、関係一覧、通知、画像の認可は権限情報を含むためPrimaryに残す。画像本体は従来のローカルファイル保存を使う。

`ReadDB`はデータ取得、`WriteDB`は書き込みと現在の権限照合に使う。
`primary_permissions.go`にPrimary照合を共通化した。
SQL文字列による自動ルーティングはしない。

## 起動・復旧と読み取り失敗

起動・復旧時には固定したPrimary flush LSNまでの追従を確認してからローカル利用へ戻す。
毎回動く最新LSNを追い続ける方式はやめ、負荷中も追従判定が完了できるようにした。
通常時はsender・slot・system identifier・timeline・recovery・replay pauseをバックグラウンドで確認し、
未再生WALがある場合にはPrimary側のreplay_lagが2秒を超えたReplicaを使わない。
正常な非同期遅延による本文の古さはあり得るが、許可判定はPrimaryに残る。

ローカル読取エラーでまだ応答を書き出していなければ、GETをPrimary経路で再実行する。
権限エラーをDB障害として再試行することや、書き込みを再試行することはない。
通常GETがPrimaryへWAL位置を問い合わせる処理は追加していない。
initializeの両Replica待機と50秒の通常期限は維持している。
