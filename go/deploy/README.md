# アプリケーションのデプロイ

```sh
bash deploy.sh isu01 isu02 isu03
```

引数にはアプリケーションサーバーのSSH名を指定します。上記は3台がアプリサーバーの
場合の例です。PostgreSQL専用サーバーは指定しません。

全台のデプロイ・起動確認に成功した後、ローカルの
`~/isucon-measurement/before_benchmark.sh` を一度実行します。
この一括スクリプトはDB専用サーバーを含む全4台の既存ログを保存し、計測対象ログの
初期化、nginx・PostgreSQLの計測設定、sar開始、Slack通知を行います。
ベンチマーク自体は手動で実行し、終了後に `~/isucon-measurement/after_benchmark.sh` を実行してください。
別の場所にある場合は `BEFORE_BENCHMARK_SCRIPT=/path/to/before_benchmark.sh` で指定できます。
スクリプトの存在・読み取り可否はデプロイ前に確認します。
デプロイ途中で失敗した場合、計測準備は実行しません。計測準備が失敗した場合は終了コード1となりますが、
デプロイ済みのバイナリは戻しません。既存の計測が実行中の場合も準備は失敗するため、
計測状態を確認し、必要な後処理を完了してから再実行してください。

ローカルでLinux/amd64のバイナリを一度ビルドし、全台の事前確認後、1台ずつ転送・
入れ替え・再起動・起動確認を行います。転送中は既存アプリを停止しません。
サービスは `isureal-go.service`、配置先は `/home/isucon/webapp/go/isureal` が既定値です。
サービスのWorkingDirectoryと配置先が一致すること、CPUアーキテクチャ、既存ファイルへの
アクセス、サービスの稼働状態を事前確認します。ExecStartがこのバイナリを起動する構成で使用してください。

必要に応じて環境変数で指定します。

```sh
DEPLOY_DIR=/home/isucon/webapp/go \
DEPLOY_SERVICE=isureal-go.service \
DEPLOY_ARCH=amd64 \
bash deploy.sh isu01 isu02 isu03
```

SSH鍵認証と、対象サービスの状態確認・再起動に対するパスワード不要のsudoが必要です。
スクリプトはsudo設定を変更しません。ビルドや事前確認で失敗した場合は反映せず、
途中のサーバーで失敗した場合は後続サーバーへのデプロイを中止します。
再起動・起動確認に失敗したサーバーは旧バイナリに戻してサービスを再起動します。
すでに反映済みの他サーバーは自動では戻しません。再起動時にはSSEを含む既存接続が切断されます。

起動確認はGoの8080番ポートへの未署名画像リクエストが403になることを検査します。
nginxの画像配信やDB整合性の検証、ベンチマークの代用にはなりません。

アプリケーションの配布対象はバイナリだけです。DBスキーマの変更やinitializeは実行しません。
デプロイ後の計測設定・ログ初期化は上記の計測スクリプトが行います。
今回の画像配信変更を初めて適用する場合は、先に
[image-cache.md](image-cache.md) のDB追加SQLとnginx設定を適用してください。
